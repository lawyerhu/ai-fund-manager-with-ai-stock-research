# 主动核实与新旧首选比较

本实验遵守 SKILL.md 的“排除主动持币”目标：正常研究在股票之间选择、持有或换仓，现金仅作为费用/交易余款。正常研究只允许维持或换股。资料不足先补查，仍不可得则由模型基于现有证据二选一；API/解析等技术失败须如实报告，宿主不得伪造模型决策。向当前对话模型的选股和新旧首选比较上下文传入该目标；本参考不读取账户、持仓、IBKR 或账户约束。

研究判断的唯一目标是从当前可执行价格出发，在合理、由模型选择的研究期限内，扣除简单且可配置的研究层交易摩擦假设后，选择预期相对收益最高的合格股票。不存在风格先验、incumbent 默认保护、固定因子权重或机械投资否决；涨幅、估值、波动、技术位置、动量、crowding、回撤、price extension、entry risk 和事件均是模型可自主权衡的证据。历史成本、浮盈浮亏、持有天数、Luna 排名和历史分数不进入本轮投资先验。事件本身不是 Alpha，也不要求短期催化剂。研究层假设不等于账户真实佣金、价差或滑点，账户级执行由外层系统另行判断。

## 选股阶段的主动核实矩阵

这一步发生在 Luna 广度筛选之后、当前对话模型最终决策之前。按 SKILL.md“分阶段完成标准”执行：全部候选统一基础研究并保存完整初选排名 → 初选 Top 5逐一补充检索深研 → 5只同一次最终比较 → 最终首选与上一轮有效首选比较。不能把初选第一名直接当作最终首选。全部候选使用相同基础标准；追加深研覆盖5只全部及上一轮旧首选。缓存和共享行业证据可节省重复请求。

由 当前对话模型 为每只候选确定本轮关键问题并按决策影响排序，不设置统一必查财务清单。以下仅为可用线索及使用时的口径纪律，不要求逐项覆盖：

- 价格、已完成K线、报价时间戳和同步的 SPY/QQQ/行业基准；执行报价与研究日线分开，不能把日线的 `last_bar_at` 当实时价格。
- 最新公司 IR/SEC 原文、收入/EPS期间、现金流及营运资本、债务、现金、资本开支、股本和其他估值调整项。
- 当前及远期估值，明确价格、盈利分母、预测期间、租赁、非控股权益和业务组合；不同口径不能直接横比。
- 固定预测期限的 EPS/收入一致预期及其修正历史；分析师目标价、评级变化或新闻标题只能另列，不能替代盈利修正。
- 公司催化剂、业绩日、监管申报、停产/检修、产品或供应链事件；日期不可靠就标 `UNKNOWN`。
- 行业和宏观驱动因素：使用适用的官方数据源核实库存、开工率、价格、利差、需求和事件日历；行业数据不能直接当作公司已实现数据。
- 流动性、波动性、回撤和下行情景；历史涨幅是结果，不是未来 Alpha 证明。

优先使用公司公告、财报、IR/SEC、交易所、政府或监管机构、官方统计机构等原始来源；具体来源由 当前对话模型 按研究问题自主选择，不限于此列表；本 Skill 不读取 IBKR，行情只能来自允许的只读研究数据或用户提供的可追溯资料。搜索摘要只用于定位线索；聚合数据须核对其原始来源、口径和可靠性。每条证据必须有 `source_url`、发布日期、报告期间/`as_of`、`retrieved_at`、结构化事实、限制和 `VERIFIED/CONFLICT/UNAVAILABLE/NOT_APPLICABLE` 状态；未实际打开的来源不能标为已核实。缺口另用 `gap_status` 区分 `VERIFIED`、`NOT_PUBLIC`、`NOT_YET_OCCURRED`、`RETRIEVAL_FAILED`、`PAID_DATA_REQUIRED`、`DERIVATION_REQUIRED`、`INSUFFICIENT_SPECIFICITY`、`CONFLICTING_EVIDENCE`、`STALE` 与 `NOT_APPLICABLE`；旧的 `UNAVAILABLE/CONFLICT` 只作兼容读取，不把它们自动解释为负面事实。

将上述证据和 `gap_audit` 以精简的脱敏 `verification_packet` 交给同一次当前对话模型研究上下文（仅 legacy API 路径才使用与 capability test 相同的 CCSwitchProvider 请求）。Top 5 packet 保留 `evidence`、`as_of_basis` 和 `gap_audit`；金融数据分区按 当前对话模型 认定的关键问题组织，已有分区可沿用但不是必填指标。每个重要 gap 至少保存 `field_name`、`symbol`、`gap_status`、`criticality`、`reason`、`source_required`、`last_checked_at`、`retrieval_attempts`、`evidence_refs`、`decision_impact` 和 `blocking_research`；`criticality` 由模型按公司/行业/thesis 判断，不按字段数量评分。实际采用的证据保存来源、观察日期、报告期间、口径和限制。禁止把长篇原始网页、重复批次输出或未经核验的模型断言直接塞入最终请求。缺口出现时先实际查询、打开原文、尝试适用的替代权威来源并做可追溯计算；不能把“还没查”直接写成 `UNAVAILABLE`。原始数据已经公开时，`DERIVATION_REQUIRED` 必须进入确定性计算，保留输入、公式、结果、`as_of` 和来源引用，不让模型补数字，也不继续作为 unresolved gap。若经过有记录的尝试仍查不到，保留精确状态和影响，不要让模型填补数字。只有同步完成的回报、估值和因子数据才能生成数值 `alpha_gap` 或 SPY/QQQ 超额预期，否则报告为 `UNKNOWN`。

任何阶段若 当前对话模型 认为仍缺少可能实质改变排名、冠军或换股方向的资料，实际补查并最多追加两轮；付费墙、不可公开或同一接口持续不可用时停止重复请求，但要记录尝试和失败原因。补查后重新评估排名，允许改变首选。不得因为普通非关键字段未知就直接输出“资料不足”；应根据已核实证据给出明确的新旧首选比较方向，分别说明关键证据完整程度和真正影响投资判断的实质不确定性，不把未知项机械转成置信度或排名扣分。由 当前对话模型 自主判断来源可靠性、数据适用性、差异成因及缺口对投资判断的重要性，自主决定置信度。资料标签与缺口清单是上下文，不是扣分指令；保留日期、口径与来源，允许依据明确输入调和或归一化，并说明重要调整。补查结束后仍缺资料或存在冲突，必须用现有可信信息选择维持或换股，并披露不确定性，不能输出拒绝判断。最终报告要列出候选覆盖率、实际核实动作、已核实字段、冲突、未解决缺口及其对结论的影响。

## 资料不足时实际做什么

这是一套由 Codex 执行检索、当前对话模型执行判断的研究工作流。当前对话模型不会因为提示词写“去查资料”而获得联网检索能力。使用当前可用的 web 搜索/打开页面及项目现有研究工具取得资料；如需行情，只允许只读市场数据，不读取 IBKR 账户/持仓接口。再把资料提交给当前对话模型。不要安装付费数据服务、购买订阅或捏造不可取得的数据。

1. 从本轮排名、深度研究、对抗审查和最终结论提取关键缺口与来源冲突。保存 gap_audit：问题、影响的决策、股票代码、查询、实际来源链接、资料发布日期/报告期间、读取时间、核实结果、仍缺内容。对新记录使用精确 `gap_status`；已合理检索但发行人/监管机构未公开用 `NOT_PUBLIC`，未来事件尚未发生用 `NOT_YET_OCCURRED`，本轮未取得公开资料用 `RETRIEVAL_FAILED`，付费源才有用 `PAID_DATA_REQUIRED`，需要计算用 `DERIVATION_REQUIRED`，问题过宽用 `INSUFFICIENT_SPECIFICITY`，来源实质冲突用 `CONFLICTING_EVIDENCE`，时点不足用 `STALE`。旧 `UNAVAILABLE/CONFLICT` 只兼容读取；未查询不是 `RETRIEVAL_FAILED`。
2. 全部候选统一基础核验后，对初选 Top 5和上一轮有效首选进一步按 当前对话模型 自主确定的关键问题研究，优先读取适用的公司及监管原文；非 Top 5 候选若有可能影响入围或排名的关键缺口，也应先定向补查再确定是否淘汰。不能把摘要提到的 SEC 文件当成已阅读。按各股投资论点补充行业特定资料，保存逐股核验记录及前后 investment_confidence、evidence_completeness；发现反证时允许降低置信度或更换首选。
3. 若论点依赖行业数据，寻找相应权威公开来源。例如炼化股查看 EIA 的成品油库存、炼厂开工率、需求和最新周报；公司报告核验实现利润率与运营情况。库存/开工率不能冒充实时裂解价差；分析师目标价不能冒充盈利预测修正。无法获得的专业数据保留未知，记录尝试及它对结论的实际影响。
4. 对上一轮有效首选按公司/行业类别核验身份和发行人资料；不能把旧报告里的标签当作新一轮已核实事实。上一轮有效首选不是实际账户持仓，不读取 IBKR 合约或账户信息。
5. 资料以股票代码和结果来源组织。每条证据保留 source_url、published_at（未知则空）、as_of/报告期间、retrieved_at、结构化事实与适用限制。保存至独立输出目录 `gap_audit.json`；上一轮有效首选资料放 `previous_selection.research`，本轮比较资料放 `comparison.json`。只有已打开核实的资料才能标为核实；搜索摘要仅是线索。
6. 首轮查询覆盖影响新旧选择的缺口后，将资料交给同一次当前对话模型新旧首选比较。比较前执行 pair evidence audit：检查两腿市场 `as_of_basis` 是否合理接近、公司经营证据是否足够新，以及是否存在一方关键 `RETRIEVAL_FAILED/STALE` 而另一方已 `VERIFIED` 且可能改变方向。若有这种 material asymmetry，写 `status=NEEDS_RESEARCH`，只生成受影响两腿的定向 `research_requests`，不重跑 Luna 或整个 Top 5；最多仍为两轮。若仍要求关键资料，实际补查后至多再评估两轮；同一付费墙、接口不可用或原始数据不公开不重复请求。每轮记录补到什么、结论是否改变；`NOT_PUBLIC`、`PAID_DATA_REQUIRED`、`NOT_YET_OCCURRED` 在合理边界后不永久阻塞，交由当前对话模型作 `KEEP_PREVIOUS`/`SWITCH_TO_NEW_FIRST` 判断并解释置信度。

补查执行与输出遵循 SKILL.md“投资判断与证据缺失分离”：搜索失败不证明事实不存在，不把未知解释为负面，不为提高置信度猜测数据。来源冲突由 当前对话模型 判断可靠性和适用性。若胜负依赖尚未解决的关键事实，优先围绕该事实研究。两轮上限不替代合理检索；最终保留缺口须引用实际查询记录、停止理由及结论影响。

`NEEDS_RESEARCH` 是交给 Codex 的继续研究信号，不是结束任务或投资弃权。读取 `research_pending.json` 的模型问题、查询方向和所需深度，实际检索后补入 packet；保留来源、日期及可追溯的 gap_audit 记录；未解决缺口的 search_record_refs 使用指向实际检索记录的 JSON pointer，例如 `/gap_audit/searches/0`，不能引用不存在的记录。已有有效阶段不重跑，沿用原候选集合，只重评受新增证据影响的阶段及下游比较，不重跑 Luna。必须核对 `evidence_assessments.json`，不得把旧 schema 的缺字段或 `_COMPLETED` 事件单独视作证据充分。最终报告将投资置信度、关键证据覆盖、补查过程和未解决缺口分列；旧结果未记录的新增概念标 `NOT_RECORDED`。

## 成对证据审计与状态推进

`pair_evidence_audit` 是比较前的结构检查，不是评分器，也不替当前对话模型选择动作。它应保存 `pair_comparison_complete`、`decision_basis_sufficient` 和 `material_asymmetry_resolved` 三个布尔字段；只有模型已经完成新旧首选的实质比较，且决策关键的检索失败已补查到合理边界，比较阶段才可标记 COMPLETE。`alpha_gap` 仍可为 `UNKNOWN`，尤其是跨行业、估值分母不同或市场数据无法可靠同步时。

不得因为 challenger 的公开资料更新更快、更完整就把信息路径本身解释成投资优势。如果现任首选的关键变量是 `RETRIEVAL_FAILED` 或 `STALE`，而 challenger 已有 `VERIFIED` 资料，先只补查受影响的两腿；补查后确认现任变量转弱，或确认该变量客观不可公开/不可获得且现有证据仍足以支持 challenger，才允许模型选择切换。`NOT_PUBLIC`、`PAID_DATA_REQUIRED` 和 `NOT_YET_OCCURRED` 不触发无限检索；它们必须说明已查来源、停止原因和对判断的影响。

`DERIVATION_REQUIRED` 不应长期留在 unresolved gap。Codex 用公开原始输入做确定性计算并保存输入、公式、结果、`as_of`、原始证据引用和 `estimate_type=DETERMINISTIC`；中周期盈利等不能确定性计算的项目才可保留为 `MODEL_ESTIMATE`，不可凭空生成数字。若当前 thesis 实质依赖炼化/能源周期，研究问题应考虑裂解价差、成品油库存、炼厂开工率、吞吐量、利润捕获率、检修/停产、盈利修订和中周期盈利，并区分利润当前处于高位与市场对持续时间预期的上修/下修；不建立固定因子公式，也不因股价已上涨或利润见顶机械扣分。

## 防止上一轮结果污染

上一轮结果用于继承最终 KEEP / SWITCH 后的 outgoing_active_selection 和审计当时的判断；不能把 selected_symbol 或排名第一名自动当作仍有效的首选。不得把上一轮的分数、旧报告中的目标仓位、现金假设或旧持仓理由直接带入本轮；旧分数不能与本轮分数相减。若上一轮有效首选为 CASH/WAIT，必须重新核验并由 当前对话模型 重新判断，不能由宿主强改成股票。

本轮新第一名和上一轮有效首选必须在同一次当前对话模型上下文中比较未来机会、证据质量、风险、催化剂和原论点是否失效。上一轮有效首选不是实际账户持仓；不读取 IBKR、账户余额、持仓快照或交易成本，也不输出账户级目标。

## 新旧首选的调仓方向

### 由当前对话模型直接作出建议

最终首选和上一轮有效首选的换股方向必须由当前对话模型根据同一批已核实证据和同一次比较上下文直接输出。Luna 的排名、历史分数和程序默认阈值都不能代替这个决定。模型必须返回 `new_first_symbol`、`previous_first_symbol`、`rebalance_decision`、`alpha_gap`、`why_new_beats_previous`、`why_keep_previous`、`confidence` 和 `confidence_reducers`，并在独立 `evidence_assessments` 中记录 `investment_confidence`、`evidence_completeness`、补查请求及未解决缺口。

宿主只做结构校验、证据引用校验、日期/口径可比性检查和安全隔离，不得自行把分数或置信度换算成调仓结论，也不得静默改写当前对话模型的动作。`alpha_gap` 只有在同一评估内可比时才能填写；否则必须为 `UNKNOWN`。

调仓方向只允许 `SWITCH_TO_NEW_FIRST` 或 `KEEP_PREVIOUS`。它们分别表示建议换到新第一名或维持上一轮有效首选；模型必须说明为什么选择该动作及为什么不选另一动作。

本流程不输出账户目标仓位、金额、股数、交易成本、资金来源或实际买卖清单。报告只说明新旧首选、相对证据、换股方向、方向依据、Bull/Base/Bear、失效条件、未知项和结果路径。新旧首选相同必须为 `KEEP_PREVIOUS`；关键比较失败不得包装成继续持有或现金建议。

只要输出 `SWITCH_TO_NEW_FIRST`，必须明确新首选相对于旧首选的可验证优势、主要反证、置信度和仍需观察的失效条件；只要输出 `KEEP_PREVIOUS`，必须明确新首选为何不足以取代旧首选。所有结果均为研究建议，未经过账户对账、Risk Engine审批或订单提交。

完整研究结束后，按 SKILL.md“跨轮有效首选状态”和“每轮正式中文报告与决策理由留存”保存四项跨轮状态并自动生成同目录中文 DOCX；可用时生成 PDF。报告只排版本次各决策阶段保存的中文理由，不另请求事后解释。
